📖 Обзор алгоритмов

AES-GCM Симметричный · Аутентифицированный

История: GCM (Galois/Counter Mode) был предложен в 2004 году Дэвидом МакГрегором и Джоном Виегой, позже стандартизирован NIST в SP800-38D. Он сочетает в себе счётчик (CTR) для шифрования и код аутентификации GHASH для проверки целостности.

Надёжность: Это режим с аутентификацией (AEAD), что означает: злоумышленник не только не сможет прочитать данные, но и любое изменение зашифрованного текста будет обнаружено при расшифровке. Именно поэтому GCM настоятельно рекомендуется для использования в Web Crypto API. AES-GCM широко применяется в TLS 1.3, IPsec и современных стандартах связи.

Особенность: Для шифрования нужен уникальный nonce (одноразовый номер). Никогда не используйте один и тот же nonce с одним ключом дважды — это фатальная ошибка. В нашем примере мы генерируем его через crypto.getRandomValues().

AES-CBC Симметричный · Устаревший

История: CBC (Cipher Block Chaining) — один из старейших режимов блочного шифрования, описан ещё в 1976 году. Каждый блок открытого текста перед шифрованием объединяется по XOR с предыдущим зашифрованным блоком, что создаёт «цепочку».

Надёжность: Сам по себе AES-CBC обеспечивает конфиденциальность, но не целостность. Злоумышленник может изменить зашифрованные данные, и вы не узнаете об этом. Классические атаки — padding oracle — позволяют расшифровывать данные при неправильной реализации. Web Crypto API не добавляет аутентификацию автоматически, поэтому CBC считается устаревшим для новых проектов.

Когда использовать: Только для совместимости со старыми системами. Если есть выбор — используйте GCM.

AES-CTR Симметричный · Потоковый

История: CTR (Counter Mode) превращает блочный шифр AES в потоковый. Вместо шифрования самих данных шифруется счётчик, а результат XOR-ится с открытым текстом. Это позволяет обрабатывать данные произвольной длины без дополнения (padding).

Надёжность: AES-CTR быстр и эффективен, но не обеспечивает аутентификацию. Если злоумышленник изменит бит в шифротексте, соответствующий бит открытого текста тоже изменится — и система не заметит подмены. Критически важно никогда не повторять счётчик с одним и тем же ключом: это раскрывает оба сообщения.

Применение: Внутренние системы, где целостность контролируется другими средствами. Для публичных каналов — не лучший выбор.

RSA-OAEP Асимметричный · Гибридный

История: RSA был изобретён в 1977 году Ривестом, Шамиром и Адлеманом. OAEP (Optimal Asymmetric Encryption Padding) — схема дополнения, предложенная в 1994 году и стандартизированная в RFC 3447. Она добавляет случайность и защиту от атак на основе подобранного шифротекста.

Надёжность: RSA-OAEP считается криптографически стойким при достаточной длине ключа (минимум 2048 бит). Однако он очень медленный и может зашифровать лишь ограниченный объём данных: например, ключ 2048 бит с SHA-256 позволяет зашифровать не более 190 байт. Поэтому RSA-OAEP обычно используют для шифрования симметричного ключа, а не самого сообщения — это называется гибридным шифрованием.

В нашем демо: Для RSA-OAEP мы генерируем ключевую пару, шифруем текст публичным ключом и выводим результат. Это наглядно показывает ограничение по длине.

Пример кода

// Web Crypto API — шифрование AES-GCM
async function encryptAESGCM(plainText, password) {
  const enc = new TextEncoder();

  // 1. Импорт пароля как ключевого материала
  const keyMaterial = await crypto.subtle.importKey(
    "raw",
    enc.encode(password),
    "PBKDF2",
    false,
    ["deriveKey"]
  );

  // 2. Произвольная соль (в реальности храните её рядом с шифротекстом)
  const salt = crypto.getRandomValues(new Uint8Array(16));

  // 3. Получение AES-ключа через PBKDF2 (100 000 итераций)
  const aesKey = await crypto.subtle.deriveKey(
    {
      name: "PBKDF2",
      salt: salt,
      iterations: 100000,
      hash: "SHA-256"
    },
    keyMaterial,
    { name: "AES-GCM", length: 256 },
    false,
    ["encrypt", "decrypt"]
  );

  // 4. Генерация nonce (12 байт для GCM)
  const iv = crypto.getRandomValues(new Uint8Array(12));

  // 5. Шифрование
  const ciphertext = await crypto.subtle.encrypt(
    { name: "AES-GCM", iv: iv },
    aesKey,
    enc.encode(plainText)
  );

  return {
    salt: btoa(String.fromCharCode(...salt)),
    iv: btoa(String.fromCharCode(...iv)),
    data: btoa(String.fromCharCode(...new Uint8Array(ciphertext)))
  };
}

⚠️ Важно: Web Crypto API работает только в безопасном контексте (HTTPS или localhost). Все операции выполняются асинхронно и возвращают Promise.

🔑 О PBKDF2: Мы используем PBKDF2 для превращения пароля в ключ. Чем больше итераций — тем медленнее подбор пароля злоумышленником. 100 000 итераций — современный минимум.

📦 Кодирование: Зашифрованные данные и параметры (соль, IV) кодируются в Base64 для удобного отображения. В реальном приложении их нужно передавать вместе с шифротекстом.

🧪 RSA-OAEP: Для демонстрации ключевая пара генерируется заново при каждом шифровании, а расшифрование выполняется тем же ключом в рамках одной сессии. В реальном приложении приватный ключ нужно хранить в защищённом хранилище.
